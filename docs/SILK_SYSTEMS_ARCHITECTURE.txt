  1.  RUNTIME STACK & CONFIGURATION
═══════════════════════════════════════════════════════════════════════════════════

  All tuning values live in a single configuration module:
  src/core/engine/ArenaConfig.ts

  This file exports five immutable const objects (all typed as const):

    CANONICAL_UNITS          Physical constants and unit-space mappings.
    ARENA_CONFIG             Geometric and spawn positions.
    GAMEPLAY_TUNING          Player, combat, and reel mechanics.
    WEAVER_AI_TUNING         Boss behavioral parameters.
    VISUAL_JUICE_CONFIG      Material, particle, tether, and emissive values.
    CAMERA_TUNING            Comfort zone bounds and scroll limits.
    POST_PROCESSING_PRESETS  Bloom, ACES, vignette, lighting, and camera presets.

  Dependency stack:

    Babylon.js 7.47.0          WebGL2 renderer with WebGPU preset support.
    @babylonjs/havok           Havok Physics V2 (WebAssembly C++ solver).
    Tone.js 15.1.22            Web Audio API wrapper with sample scheduling.
    Zustand 5.0.13             ECS-to-React state bridge.
    Framer Motion              HUD and overlay animation.
    canvas-confetti            Victory screen particle burst.
    Vite 8 + TypeScript 6      Build system. Strict mode; no explicit `any`.

  TypeScript compiler constraints enforced:
    - noUnusedLocals, noUnusedParameters
    - no explicit `any` types anywhere
    - All dynamically resolved types cast through `unknown` + type guards

  4.  ENGINE LOOP & TIMESTEP MODEL
═══════════════════════════════════════════════════════════════════════════════════

  File:  src/core/loop/GameLoop.ts

  Silk uses a semi-fixed timestep integration model to decouple physics updates
  from variable display refresh rates.

  Constants:
    Fixed update step     dt = 1/60 s (16.67 ms)
    Accumulator ceiling   100 ms — prevents "spiral of death" on slow devices

  Each tick:
    1. Advance accumulator by real elapsed time.
    2. While accumulator >= fixedStep:
         · Apply timeScale from RuntimeState (slomo / adrenaline).
         · Run all update-phase systems with scaled dt.
         · Decrement accumulator by fixedStep.
    3. Compute interpolation alpha:
         alpha = accumulator / fixedStep
    4. Run all render-phase systems with alpha (sub-frame interpolation).

  The alpha value is passed to EntityInterpolationSystem and ParallaxScrollSystem
  so entity positions and scroll offsets render smoothly between physics frames.

  Scheduler:  RafScheduler.ts wraps requestAnimationFrame with clamped delta.
  Clock:      PerformanceClock.ts uses performance.now() for sub-millisecond accuracy.

  6.  PHYSICS ARCHITECTURE & COPLANAR SANDWICHING
═══════════════════════════════════════════════════════════════════════════════════

  File:  src/physics/havok/HavokPhysicsSystem.ts
         src/physics/systems/

  Project Silk runs 2D gameplay logic inside a 3D rigid-body solver using a
  technique called "Coplanar Physics Sandwiching."

  6.1  Rigid Body Configuration
  ─────────────────────────────
  The player capsule and Weaver icosphere are both ANIMATED-type rigid bodies
  (BABYLON.PhysicsMotionType.ANIMATED). Their positions are driven by the ECS
  kinematics systems, not by solver forces. Each frame, the ECS writes target
  coordinates and orientations to the physics body via body.setTargetTransform().
  This lets game code own the motion math while the Havok solver handles collision
  geometry detection and event broadcasting.

  6.2  Coplanar Sandwiching Geometry
  ───────────────────────────────────
  To prevent Z-axis drift or rotational torque from explosive forces, five static
  box colliders sandwich the play area:

    Name         Dimensions [W, H, D]       Center [X, Y, Z]    Friction  Restitution
    ─────────────────────────────────────────────────────────────────────────────────
    physFloor    [32.4, 1.0, 16.0]          [0.0, -9.0, 0.0]    0.50      0.25
    physLeft     [1.0, 140.0, 16.0]         [-14.7, 14.0, 0.0]  0.30      0.40
    physRight    [1.0, 140.0, 16.0]         [14.7, 14.0, 0.0]   0.30      0.40
    physFront    [32.4, 140.0, 1.0]         [0.0, 14.0, -3.5]   0.10      0.50
    physBack     [32.4, 140.0, 1.0]         [0.0, 14.0, 3.5]    0.10      0.50

  All Z-motion is constrained to Z ∈ [-3.5, 3.5]. Residual depth forces are
  absorbed into physFront/physBack wall friction, maintaining coplanar stability.

  6.3  Spatial Query Service
  ──────────────────────────
  File:  src/physics/systems/SpatialQueryService.ts

  Provides raycasting and broadphase overlap queries against the Havok solver.
  Used by PlayerKinematicsSystem (wall-cling raycasts at length 0.15m),
  CombatSystem (player–Weaver proximity), and ProjectileSystem.

  6.4  Environment Clamping
  ─────────────────────────
  File:  src/physics/systems/EnvironmentClampingSystem.ts

  Runs post-physics as a hard-override guard. Clamps entity X positions to
  ARENA_CONFIG.HORIZONTAL.WALL_LIMIT_X (±14.2) and Y positions to floor bounds.
  Ensures the solver cannot produce positions outside the visual arena geometry
  even under extreme impulses.

  7.  PLAYER STATE MACHINE & TRAVERSAL KINEMATICS
═══════════════════════════════════════════════════════════════════════════════════

  Files:  src/gameplay/player/PlayerKinematicsSystem.ts
          src/gameplay/player/states/

  The player has three concrete states implementing IPlayerState.ts:
  AIRBORNE · WALL_STICKING · LAUNCHING

  ┌──────────────────────────┐
  │         AIRBORNE         │◄─────────────────────────┐
  └────────────┬─────────────┘                          │
               │ Wall contact +                         │
               │ lateral input toward wall              │ Launch timer expires
               ▼                                        │ (0.7 s) or control
  ┌──────────────────────────┐                          │ returns
  │      WALL_STICKING       │                          │
  └────────────┬─────────────┘                          │
               │ Tension ≥ 0.427 +                      │
               │ charge input released                  │
               ▼                                        │
  ┌──────────────────────────┐                          │
  │        LAUNCHING         ├──────────────────────────┘
  └──────────────────────────┘

  7.1  Airborne State  (PlayerAirborneState.ts)
  ─────────────────────────────────────────────
  Gravity:     G_kinematic = -24.0 m/s²
  Swing force: F_swing = 36.0 m/s²
  Drag:        V(t) = V(t) * (0.99)^(dt * 60)

  Velocity integration:
    V_y(t) = V_y(t-1) + G_kinematic * dt
    V_x(t) = V_x(t-1) + Input_x * F_swing * dt

  Wall-cling evaluation: Horizontal raycasts of length 0.15m. If the player
  position.x exceeds ±13.6 (WALL_CLING_THRESHOLD_X) and input steers toward that
  wall, the player transitions to WALL_STICKING.

  7.2  Wall Sticking State  (PlayerWallStickingState.ts)
  ───────────────────────────────────────────────────────
  Lateral velocity is zeroed. Vertical slide:
    V_y = -(V_slide + V_hazard_speed)

  Where V_slide = 5.0 m/s base, and V_hazard_speed is non-zero when sticking
  to a moving WallBug or SpikeBug (conforms the slide to the hazard's velocity).

  Charge phase begins when the player holds the wall. chargeTimer begins
  accumulating once tension exceeds 0.427 (TETHER_UI.THRESHOLD_YELLOW). The
  charge ratio clamps to a normalized [0, 1] value used to scale fling power.

  7.3  Launching State  (PlayerLaunchingState.ts)
  ─────────────────────────────────────────────────
  Gravity is scaled during launch to enable linear trajectories:
    G_launch = G_kinematic * 0.22 = -5.28 m/s²

  Lateral steering during launch:
    V_x(t) = V_x(t-1) + Input_x * 16.0 * dt

  Auto-exits to AIRBORNE after 0.7 s (GAMEPLAY_TUNING.PLAYER.LAUNCH_DURATION).

  7.4  Fling Launch Vector (3 Tension Stages)
  ────────────────────────────────────────────
  File:  src/gameplay/player/states/PlayerStateUtils.ts

  Stage 1 — Slack Zone (T < 0.427):
    Player drops with a gentle nudge away from the wall.
    V_launch = [N_wall * 5.5,  max(V_y, -3.0),  0]

  Stage 2 — Taut Zone (0.427 ≤ T < 0.8):
    Launches toward the Weaver anchor tip.
    V_launch = D_anchor * I_fling * 0.55 * S_length * R_charge * B_bonus
    Where:
      I_fling  = 76.0 m/s (FLING_IMPULSE)
      S_length = length scalar based on current rope extension
      R_charge = charge timer ratio [0, 1]
      B_bonus  = 1.15 (web-struggle bonus multiplier)

  Stage 3 — Overloaded Zone (T ≥ 0.8):
    Maximum kinetic release. Base power ratio = 0.90.
    Triggers chromatic aberration pulse and hitstop time-dilation.

  7.5  Squash-Stretch on Launch
  ──────────────────────────────
  File:  src/gameplay/player/PlayerAnimationSystem.ts

  On fling:
    Sweet-spot launch:   ScaleVel_Y = +22.0, ScaleVel_X = -11.0
    Overloaded launch:   ScaleVel_Y = +36.0, ScaleVel_X = -18.0

  On wall landing:
    ScaleX = 0.72, ScaleY = 1.22 (squash toward wall)
  On floor landing (V_y < -1.0):
    ScaleX = 1.22, ScaleY = 0.72 (squash downward)

  All scale deformations are spring-damper resolved each frame (see Section 13).

  8.  TETHER MECHANICS: TENSION, REELING & SNAP-BACK
═══════════════════════════════════════════════════════════════════════════════════

  Files:  src/gameplay/player/TetherReelingSystem.ts
          src/gameplay/player/TetherStrainSystem.ts

  The tether is the primary game mechanic. Its length can be reeled in/out
  manually and is punished by the Weaver's attacks.

  8.1  Rope Length Solver  (TetherReelingSystem.ts)
  ──────────────────────────────────────────────────
  Manual reel-in speed (UP key): -16.0 m/s (REEL.MANUAL_IN_SPEED)
  Min length: 5.4 m     Max length: 38.0 m

  The maximum allowed length (L_max) is spring-damper interpolated toward
  the desired length (L_desired) to produce smooth reeling dynamics:

    [L_max, V_reel] = solveSpringDamper(L_max, L_desired, V_reel, dt,
                                        K=180.0, D=15.0)

  8.2  Tautness Ratio
  ────────────────────
    R_taut = L_current / L_max

  8.3  Elastic Tension Formula
  ─────────────────────────────
  Tension is zero inside the slack zone (R_taut < 0.85):

    T = clamp(0, T_max,  (R_taut - 0.85) / 0.15)

  Dynamic tension ceiling (prevents instant snaps when reeled short):

    T_max = clamp(0.15, 1.0,  (L_max - 5.4) / (38.0 - 5.4))

  8.4  Tension HUD Color Thresholds
  ───────────────────────────────────
    Green   : T < 0.427
    Yellow  : 0.427 ≤ T < 0.8      (threshold to enter LAUNCHING)
    Red     : T ≥ 0.8              (overload zone; max fling power)

  The HUD tension bar bypasses React state entirely for performance-critical
  updates. HudSyncSystem writes width, color, and glow CSS box-shadow directly
  to DOM element refs via a custom `silk-tension-render-tick` event.

  8.5  Violent Snap-Back Recoil  (TetherStrainSystem.ts)
  ────────────────────────────────────────────────────────
  Triggered when T reaches 1.0 (SNAP_LIMIT). Sequence:

    1. Forces player into AIRBORNE with a 0.5 s control stun.
    2. Halves the max tether capacity: L_max *= 0.5.
    3. Whips the player toward the Weaver at 55.0 m/s:
         V_snap = D_anchor_unit * 55.0
    4. Applies hard squash to the Weaver: ScaleVel = [-28.0, 18.0, 0].
    5. On the 3rd consecutive snap hit, the thread is fully cut → instant death.
    6. A scroll pause is applied for visual weight (tetherDamagePauseTimer).

  9.  WEAVER BOSS AI
═══════════════════════════════════════════════════════════════════════════════════

  Files:  src/gameplay/weaver/
          src/gameplay/weaver/states/

  The Weaver is a state machine with five concrete states implementing IWeaverState.

  Berserk threshold:  HP < 50% of maximum (WEAVER_AI_TUNING.BERSERK_HP_THRESHOLD).
  In berserk mode, patrol speed doubles and dash speed increases by ~29%.

  ┌──────────────────────┐
  │      PATROLLING      │◄─────────────────────────────────────────┐
  └──────────┬───────────┘                                          │
             │ Player lands a fling hit  ──or──                     │
             │ player physically contacts Weaver                    │
             │                                                      │
             ▼                                                      │
  ┌──────────────────────┐  player contact          ┌───────────────┤
  │       STRIKING       │─────────────────────────►│   SHOCKWAVE   │
  └──────────┬───────────┘  (shockwave branch)      └───────┬───────┘
             │ Dash/recover complete                        │ Blast resolved
             │                                              │
             └──────────────────►┌──────────────────────┐◄──┘
                                 │      ASCENDING       │
                                 └──────────┬───────────┘

  11.  VERTICAL SCROLL & ALTITUDE SYSTEM
═══════════════════════════════════════════════════════════════════════════════════

  File:  src/visual/systems/ParallaxScrollSystem.ts

  The entire arena scrolls upward continuously during active gameplay, creating
  the illusion of a vertical elevator shaft. The player is not scrolled — instead
  all world geometry moves downward relative to the static camera viewport.

  Scroll speed (base): 6.75 m/s      (ARENA_CONFIG.SCROLL_SPEED.BASE)
  Scroll speed (berserk): 11.25 m/s  (SCROLL_SPEED.BERSERK, i.e. BASE * 1.5)
  Scroll speed (dash):     0.0 m/s   — scroll paused during Weaver strike/shockwave.

  The current scroll speed is lerped toward the target each frame (factor 0.15),
  preventing jarring speed changes. It is also zeroed during hitstop and tether
  damage pause timers.

  Altitude accumulation:
    runtime.altitude += scrollSpeed * dt  (only when scrollSpeed > 0)
  This value is used by ProfilePersistenceSystem at match end.

  Geometry wrapping:
    Arena scrollable meshes (tagged metadata.type = "scrolling_*") are tracked in
    a cached array. Each frame their Y positions are recalculated:

      wrappedOffset = currentScrollOffset % TOTAL_RANGE (140.0 m)
      element.Y = initialY - wrappedOffset
      while Y < BOTTOM_BOUNDARY (-56.0): Y += 140.0
      while Y > TOP_BOUNDARY   (+84.0): Y -= 140.0

    This creates seamless infinite-loop scrolling across the 140 m scroll domain.

  Camera Y offset compensation: Wall and backdrop meshes are additionally offset
  by the camera's Y pan (from CameraSystem) to track the viewport during boss
  engagement scrolling.

  InterpolatedOffset = prevOffset + (currentOffset - prevOffset) * alpha
  ensures sub-frame smooth rendering without judder.

  12b.  Camera System

  File:  src/visual/cameras/CameraSystem.ts

  12d.  Procedural Shader Plugins  (SilkMaterialPlugin.ts)
  ─────────────────────────────────────────────────────────
  File:  src/visual/lighting/SilkMaterialPlugin.ts

  A Babylon.js MaterialPlugin injected onto PBR materials at runtime.
  Supports two independent shader modes, both using vertex-displacement
  and custom normal reconstruction.

  Mode 1 — Damage Shear Displacement (Weaver body on hit):

    Quantized tile sin-wave applied horizontally to vertex Y slices:

      D_shear = floor(P_y / 0.16) * 0.16
              * sin(floor(P_y / 0.16) * 0.16 * 20 + t * 75)
              * E(y, t)
              * I_damage

    Gaussian shiver envelope:
      E(y, t) = max(0, 1 - |P_y - (2.5 - t * 10.0)| / 1.8)

    Normal reconstruction via finite-difference (ε = 0.02):
      N_sheared = normalize(N - [(D_shear(P + ε_y) - D_shear(P)) / ε, 0, 0] * 0.35)

  Mode 2 — Noise Displacement (Projectile / Cocoon web shading):

    Trig-noise sine product displaced along mesh normals:
      D_noise = (sin(Px*2 + t*5) * cos(Py*2.3 + t*6.3) * sin(Pz*2.6 + t*4.1)
               + sin(Py*5 - t*11) * 0.35) * 0.24

    P_new = P + N * D_noise

    3D finite-difference gradient for normal update:
      G = (1/ε) * [D(P+εx)-D(P), D(P+εy)-D(P), D(P+εz)-D(P)]
      N_new = normalize(N - G * 0.5)

  Abdomen Under-Glow (fragment shader — Weaver):

    Bioluminescent emission along the Weaver's lower abdomen:
      F_glow = smoothstep(0, 3.4, -P_y_local)^2.5
      C_final = C_base + C_emissive * F_glow

  12e.  Procedural Texture Generation
  ─────────────────────────────────────────────
  File:  src/visual/scene/ProceduralTextureGenerator.ts

  All arena surface textures are generated at boot via HTML5 Canvas 2D contexts.
  No external texture files loaded for arena geometry. Mobile devices receive
  reduced resolution (256–512 px) vs. desktop (512–1024 px).

  fBm noise (4 octaves):
    f(x, y) = Σ_{i=0}^{3} A_i * noise(x * F_i, y * F_i)
    A_0 = 0.5, A_{i+1} = A_i * 0.5
    F_0 = 1.0, F_{i+1} = F_i * 2.0

  Output textures per material set:

    Albedo map:    fBm-perturbed color with colorVariation parameter.
    Normal map:    Horizontal (dx) and vertical (dy) gradients packed into RGB.
                   Color_normal = [(dx*0.5+0.5), (dy*0.5+0.5), dz] * 255
    ORM map:       Packed AO / Roughness / Metalness per-pixel:
                     R: AO = 1 - (1 - height) * 0.3
                     G: Roughness = R_min + (1-height) * (R_max - R_min)
                     B: Metalness = 0.95 * 255 (constant)
    Ridge detail:  Optional ridge-variation pass for concrete backwall.

  Texture cache:  ProceduralTextureGenerator.clearCache() is called on
  RenderSystem.dispose() to release VRAM.

  12f.  Tether Rope Geometry
  ─────────────────────────────────────────────
  File:  src/gameplay/juice/TetherVisualizerSystem.ts

  The tether is rendered as a dynamic cylinder tube re-triangulated every frame.
  24 segments (TETHER_ROPE.SEGMENTS).

  Quadratic Bezier curve:
    B(t) = (1-t)² * A  +  2(1-t)t * C  +  t² * P
    t ∈ [0, 1], 24 steps. A = anchor point, P = player attachment, C = control.

  Control point (sag calculation):
    C = midpoint(A, P) - [0, S_sag, -0.35]
    S_sag = S_max * (1 - T_tension) + Osc_vibe
    S_max = 3.8 m

  Cable vibration at high tension:
    If T > 0.7:
      Osc_vibe = sin(time * 0.025) * (T - 0.7) * 0.35
    If T > 0.95:
      Amplitude *= 2.5, frequency *= 3.5

  Tube radius varies by tension state:
    Slack:         BASE_RADIUS * 0.85  = ~0.06 m
    Sweet spot:    MAX_RADIUS * 1.1    = ~0.14 m
    Plus a slow pulse: sin(time * 0.03) * 0.015 to simulate strand life.

  Wind wave depth disturbance:
    P_z += sin(segIndex * 2.5 + time * 0.005 + φ_reel) * 0.12
    φ_reel = phase offset proportional to current reeling speed.

  Double-strand snap model (on tether break, 1.5 s decay):
    Anchor strand (first 12 segs):
      Free end whips:  Whip = sin(t_snap * 5π) * (1 - t_snap) * 1.8 m
    Player strand (remaining 12 segs):
      Free end falls:  Fall = t_snap² * G_gravity * 0.8

  Files:  src/visual/mesh/WeaverVisualFactory.ts

  Weaver mesh:  Procedurally assembled icosphere body (subdivisions=5, radius=4.4m)

    Weaver gait cycle:  Driven by gaitClock (accumulated dt * gaitFreq).
    gaitFreq is derived from Weaver's relative speed vs. scroll speed.
    Diagonal alternating phase offset per leg pair for natural gait.

    Two-level solver:
      Level 1 — Fallback (no base foot data):  Pure trigonometric sine/cosine
        sweep applied to coxa and tibia rotation.z.
      Level 2 — Full IK (with base foot data):  Analytic 2-bone IK resolves
        foot placement in Weaver-local space after world transform inversion.
        Foot targets are clamped to arena bounds (±15m X, -8 to 38 Y) before
        being projected back to local space.

    2-Bone IK solver:
      Input: target local position, coxa length L1, tibia length L2, side sign.
      Output: coxaZ rotation angle, tibiaZ rotation angle.

        d = length(target_local.xy), clamped to [|L1-L2|+ε, L1+L2-ε]
        β = acos((L1² + d² - L2²) / (2*L1*d))   [elbow bend angle]
        γ = acos((L1² + L2² - d²) / (2*L1*L2))  [knee angle]
        coxaZ  = atan2(-x, y) ± β  (sign by side)
        tibiaZ = ±(π - γ)

  Body sway (VisualStateDressingSystem.ts):
    abdomen, cephalothorax, and head nodes undergo idle sway each frame:
      bodySway = sin(clock * 4.0) * 0.05 * 0.16
      bodyBob  = cos(clock * 8.0) * 1.5 * 0.008
    Each part receives a scaled fraction with position and rotation offsets
    stored in node.metadata.baseX/Y/Z on first execution.

  Spawned at 60% Weaver HP. Fly slowly downward from the upper arena.

  When the player contacts a health bug, it ruptures and grants +1 HP recovery
  (capped at player MAX_INTEGRITY). Publishes HEALTH_BUG_RUPTURED event.
  SFX: health_bug_rupture.mp3.

  Health bugs can also be destroyed by spiked hazards (HEALTH_BUG_RUPTURED
  with bySpikes=true payload) — they break without granting HP.

    Δ_cents ∈ ±50 to ±250 cents (random per play).
    Gain offset:  ±2.5 dB random per play.

  15.2  Procedural Wind Synthesis  (ProceduralAmbienceEngine.ts)
  ──────────────────────────────────────────────────────────────
  Generates atmospheric background wind without audio files.

  Web Audio graph:

    [White Noise]
         ↓
    [Lowpass Filter 1 — 800 Hz cutoff]
         ↓
    [Lowpass Filter 2 — 300 Hz base cutoff]
         ↓                          ↑ modulated by
    [Gain]                    [LFO 0.2 Hz × LFO Gain 10]
         ↓
    [AudioContext Destination]

  LFO modulates Filter 2 cutoff frequency, creating natural wind gust rhythm.
  Gain smoothed over 2.0 s on startup via linearRampToValueAtTime.

  16.  UI ARCHITECTURE & REACT–ECS BRIDGE
═══════════════════════════════════════════════════════════════════════════════════

  Files:  src/ui/hud/
          src/ui/cursor/

  16.1  Zustand Store Topology
  ──────────────────────────────
  File:  src/ui/hud/hudStore.ts

  Four stores maintained:

    usePlayerStore     playerHp, currentState, isWebTrapped, escapeProgress,
                       escapeRequired, webMass, tetherDamage.

    useWeaverStore     weaverHp, weaverMaxHp, weaverState, weaverHue.

    useOverlayStore    Boot progress (phase, status, logs, loadingProgress),
                       traversalHint (text/color/opacity), match overlays
                       (title/color/subtitle), isPaused, awaitingGesture,
                       wins/losses counters, calibrationStep, publishEvent bridge.

    useInputStore      keysPressed: Record<string, boolean> (for calibration UI).

  All setters include referential equality guards — returns {} if unchanged —
  preventing unnecessary React renders on high-frequency ECS updates.

  resetAllStores() resets all four stores to initial state; called by
  GameDirectorSystem on GAME_RESET. wins/losses persist across resets.

  16.2  HudSyncSystem  (ECS → React Bridge)
  ───────────────────────────────────────────
  File:  src/ui/hud/HudSyncSystem.ts

  Runs in Phase 6 (RenderSync). Reads ECS component stores each frame and
  calls Zustand store setters. Only updates that produce actual state changes
  propagate into React.

  High-frequency exception — tension bar bypass:
    Rather than route the tension value through Zustand → React → DOM,
    HudSyncSystem writes the tension bar width, background-color, and
    box-shadow directly to DOM refs via a custom `silk-tension-render-tick`
    CustomEvent, avoiding React reconciliation on every frame.

  16.3  HUD Overlay  (HudOverlay.tsx)
  ─────────────────────────────────────
  File:  src/ui/hud/HudOverlay.tsx

  React component tree (all animated via Framer Motion + AnimatePresence):

    Boot sequence:   4-step loading screen with phase-locked step icons.
    Gesture gate:    Locked overlay released on first user interaction.
    Gameplay HUD:    HP pips (5 hearts), Weaver HP bar, tension bar, traversal hint.
    Web trap UI:     Cocoon scale indicator + directional struggle prompt.
    Pause overlay:   Pause state display.
    End screens:     VICTORY (emerald) / DEFEATED (red) with MenuButton options
                     (Replay / Clear Data), animated stagger reveal.
    Win/loss ticker: Persistent per-session counter.
    Calibration:     Step 0 — "Stick to Wall" tutorial prompt with animated keycap UI.
                     Step 1 — fling instruction displayed on first successful stick.

  Custom cursor system (src/ui/cursor/):
    CursorLayer.tsx provides a canvas-based software cursor.
    useCursorStore.ts (Zustand) tracks cursor type.
    CursorVariants.ts defines cursor appearance per interaction state.

  Error boundary (ErrorBoundary.tsx) wraps HudOverlay to prevent HUD crashes
  from propagating to the Babylon.js engine.

  16.4  Tutorial System  (TutorialSystem.ts)
  ─────────────────────────────────────────────
  Tracks wall-stick calibration. Two steps:
    Step 0:  Player successfully sticks to a wall with tension ≥ 0.555.
             Publishes UI_CALIBRATION_STEP_CHANGED {step: 1} + UI_SFX_DING.
    Step 1:  Displayed after step 0 success. Not yet gated by an additional action.

  Resets to step 0 on GAME_RESET.

  17.  EVENT SYSTEM & COMMAND BUS
═══════════════════════════════════════════════════════════════════════════════════

  Files:  src/core/events/EventBroker.ts
          src/core/events/GameEvents.ts
          src/core/commands/CommandBus.ts
          src/core/utils/EngineUtils.ts  (SubscriptionTracker)

  17.1  Event Broker
  ──────────────────
  Typed publish/subscribe model. All events are defined in GameEvent enum with
  corresponding GameEventMap interface for payload type safety.

  Full event catalog:

    Lifecycle:         GAME_INITIALIZED, GAME_BOOT_PROGRESS, GAME_STARTED,
                       USER_GESTURE_REGISTERED, GAME_OVER, GAME_WIN, GAME_RESET,
                       GAME_PAUSED.

    Player:            PLAYER_HEALTH_CHANGED, PLAYER_DAMAGED, PLAYER_DIED,
                       PLAYER_STATE_CHANGE, PLAYER_LANDED, PLAYER_WALL_HIT.

    Tether:            TETHER_TENSION_CHANGE, TETHER_LENGTH_CHANGE.

    Weaver:            WEAVER_STATE_CHANGE, WEAVER_DAMAGED, WEAVER_HEALTH_CHANGED,
                       WEAVER_DIED, WEAVER_SHOOT, WEAVER_WALL_HIT, WEAVER_BOUNCED.

    Projectile:        PROJECTILE_IMPACT.

    Camera:            CAMERA_SHAKE_TRIGGERED.

    Input:             PLAYER_INPUT_KEY_STATE_CHANGED.

    Hazards:           HEALTH_BUG_RUPTURED.

    UI:                UI_CALIBRATION_STEP_CHANGED, UI_SFX_TICK, UI_SFX_CONFIRM,
                       UI_SFX_REVEAL, UI_SFX_DING.

  EventTrafficTracker.ts provides optional per-event frequency monitoring
  (debug/profiling use only).

  17.2  SubscriptionTracker
  ──────────────────────────
  Utility class (EngineUtils.ts) that accumulates subscription unsubscribe
  callbacks and releases them all in a single tracker.clear() call.
  Used in every system that subscribes to events to ensure leak-free disposal.

  17.3  Command Bus  (CommandBus.ts)
  ────────────────────────────────────
  Separate channel for imperative one-way commands (e.g. PhysicsCommands.ts).
  Used where a system needs to issue a side-effecting operation (like applying
  an impulse to a physics body) without routing through the event pub/sub graph.

  18.  DEPLOYMENT PIPELINE
═══════════════════════════════════════════════════════════════════════════════════

  File:  .github/workflows/deploy.yml

  Trigger: push to `main` or `master` branch.

  Steps:
    1. Checkout repository.
    2. Setup Node 20 with npm cache.
    3. `npm ci` — clean install.
    4. `npm run build` — Vite production build → /dist.
    5. Configure GitHub Pages artifact.
    6. Upload /dist as Pages artifact.
    7. Deploy to GitHub Pages (id-token write permission).
    8. Setup Butler (remarkablegames/setup-butler@v3).
    9. `butler push dist stevencasteel/silk:html5`
       Deploys to itch.io via BUTLER_API_KEY secret.

  Both deployment targets receive the same /dist build artifact simultaneously.
  Vite base path should be configured correctly for GitHub Pages subdirectory
  routing if needed.
