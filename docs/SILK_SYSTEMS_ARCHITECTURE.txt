1. SYSTEM STACK & BOOTSTRAP PIPELINE
-------------------------------------------------------------------------------
Project Silk is built upon a decoupled, web-native architecture utilizing a 3D
graphics engine, a rigid-body physics solver, a web-audio synthesizer, and a
state-synchronization layer.

1.1 Runtime Dependency Stack
    - Render Pipeline: Babylon.js 7.47.0 (WebGPUPreset / WebGL2 Fallback)
    - Physics Engine: Havok Physics V2 (via @babylonjs/havok WebAssembly compiled C++ solver)
    - Audio Engine: Tone.js 15.1.22 (Web Audio API graph wrapper)
    - State Management: Zustand 5.0.13 (Decoupled React-to-Engine bridge)
    - Build System: Vite 8.0.12 + ESBuild + TypeScript 6.0.2 compiler

1.2 Bootstrap Pipeline (`src/app/bootstrap.ts` & `CompositionRoot.ts`)
    The engine initializes asynchronously across four distinct phases defined in 
    `SystemPhase.ts` (`InitPhase` enum):

    - Phase 0: InitPhase.Bootstrap
      * Spawns core event loop scheduler (`RafScheduler.ts`).
      * Mounts high-precision performance clock (`PerformanceClock.ts`).
      * Instantiates system event broker (`EventBroker.ts`) and command bus (`CommandBus.ts`).
      * Preloads WebAssembly binaries (`HavokPhysics.wasm`) with a 3000ms timeout race 
        condition. Fallback maps from local directory to Cloudflare CDN if local loading fails.
      * Instantiates `HavokPhysicsSystem.ts` and configures the global gravity vector:
        G = [0, -9.81, 0] m/s²

    - Phase 1: InitPhase.World
      * Builds camera rigs and rendering pipelines (`RenderSystem.ts`).
      * Loads prefiltered environment specular map (`environmentSpecular.env`).
      * Spawns static elevator shaft geometry (`ArenaGeometry.ts`).
      * Compiles PBR materials and generates procedural textures (`ProceduralTextureGenerator.ts`).

    - Phase 2: InitPhase.Gameplay
      * Spawns Player and Weaver entities (`EntitySpawnerSystem.ts`).
      * Assembles ECS component stores and registers shadow casters.
      * Pre-allocates object pools for projectiles and hazards.

    - Phase 3: InitPhase.UI
      * Mounts React HUD overlays (`HudOverlay.tsx`).
      * Binds window resize, keyboard, and pointer event listeners (`PlayerInputSystem.ts`).
      * Preloads Web Audio buffers into Tone.js players (`AudioSystem.ts`).
      * Publishes global `READY` state to dismiss bootstrap blockers on user gesture.

2. ENGINE PIPELINE, SCHEDULING, & DATA TOPOLOGY
-------------------------------------------------------------------------------
Project Silk implements a custom Entity Component System (ECS) to enforce cache
locality and maintain strict decoupling between data schemas and behavioral execution.

2.1 Data Topology
    - Entities (`src/core/ecs/Entity.ts`):
      Represented as simple 32-bit unsigned integer keys (`EntityId = number`).
      Managed by `EntityRegistry.ts` which tracks active allocations with an ES6 Set.
    - Components (`src/core/ecs/ComponentStore.ts` & `Components.ts`):
      Pure data containers containing zero logic.
      Stored inside type-safe `ComponentStore<T>` collections mapping `EntityId` keys
      directly to component schemas.
    - System Context (`src/core/engine/SystemContext.ts`):
      A dependency-injection container passing references to EcsWorld, EventBroker,
      CommandBus, EntityRefs, StoreContainer, and RuntimeState.

2.2 Core Loop & Timestep Integration (`src/core/loop/GameLoop.ts`)
    The engine implements a semi-fixed timestep integration model to decouple physics
    updates from variable display refresh rates (Hz).
    - Fixed update timestep: dt = 1 / 60 seconds (16.66ms per step).
    - Maximum accumulator ceiling: 100ms (0.1s) to prevent "spiral of death" lockups on slow devices.
    - Variable rendering pass: Calculates interpolation alpha ratio:
      alpha = accumulator / fixedStep
      This alpha value is propagated to `EntityInterpolationSystem.ts` and 
      `ParallaxScrollSystem.ts` to solve rendering positions smoothly between the current
      and previous physics frames.

2.3 Execution Pipeline (`src/core/systems/SystemManager.ts`)
    Systems are updated sequentially in an 8-phase chronological pipeline.
    Below is the complete execution order:

    Phase | System Class Name             | Primary Operations & Inter-system Dependencies
    ------+-------------------------------+---------------------------------------------------------
    0     | PlayerInputSystem             | Polls keys/touch coordinates, sets `InputIntentComponent`.
    ------+-------------------------------+---------------------------------------------------------
    1     | WeaverBrainSystem             | Updates active behavioral states of the Weaver AI.
          | EntitySpawnerSystem           | Instantiates dynamic hazards based on combat thresholds.
    ------+-------------------------------+---------------------------------------------------------
    2     | PlayerKinematicsSystem        | Integrates player movement vectors, resolves pendulums.
          | TetherReelingSystem           | Updates tether target boundaries and reeling offsets.
          | WeaverTraversalSystem         | Resolves Weaver horizontal sweeps and ceiling bounds.

    ------+-------------------------------+---------------------------------------------------------
    3     | VerticalBoundarySystem        | Clamps player to viewport limits; fires impact squash.
          | TetherStrainSystem            | Evaluates cable stress, processes snap-back recoil.
          | WallBugSystem                 | Moves crawling wall hazards; steps gait phase cycles.
          | SpikeBugSystem                | Resolves crawling spike bugs; updates hazard bounds.
          | HealthBugSystem               | Coordinates flying health bugs and recovery tracking.
    ------+-------------------------------+---------------------------------------------------------
    4     | HavokPhysicsSystem            | Synchronizes ECS transforms with Havok rigid-body states.
    ------+-------------------------------+---------------------------------------------------------
    5     | CombatSystem                  | Evaluates Player-to-Weaver proximity, resolves overlaps.
          | HealthSystem                  | Processes damage pipelines and iframe cooldown timers.

    7     | ProfilePersistenceSystem      | Commits game-over metrics to client-side LocalStorage.

3. PHYSICS ENGINE & COPLANAR SANDWICHING
-------------------------------------------------------------------------------
Project Silk implements a custom architectural paradigm called "Coplanar Physics
Sandwiching" to resolve 2D simulation logic natively within a 3D rigid-body solver.

3.1 Rigid Body Configuration
    The player capsule and Weaver icosphere are initialized as `BABYLON.PhysicsMotionType.ANIMATED`
    rigid bodies within the Havok WebAssembly solver. Kinematic integration is solved
    by the ECS, and target coordinates are synchronised with the physics thread every
    step using `body.setTargetTransform()` in `HavokPhysicsSystem.ts`.

3.2 Coplanar Sandwiching Geometry
    To prevent Z-axis drift or rotational torque deviations from explosive forces,
    the play area is sandwiched between two static, invisible box barriers parallel
    to the XY plane:

    Barrier Name | Thickness / Scale             | Global Coordinates (Center) | Physical Material
    -------------+-------------------------------+-----------------------------+-----------------------
    physFloor    | [W: 32.4, H: 1.0, D: 16.0]    | [0.0, -9.0, 0.0]            | Fric: 0.5, Rest: 0.25
    physLeft     | [W: 1.0, H: 140.0, D: 16.0]   | [-14.7, 14.0, 0.0]          | Fric: 0.3, Rest: 0.40
    physRight    | [W: 1.0, H: 140.0, D: 16.0]   | [14.7, 14.0, 0.0]           | Fric: 0.3, Rest: 0.40
    physFront    | [W: 32.4, H: 140.0, D: 1.0]   | [0.0, 14.0, -3.5]           | Fric: 0.1, Rest: 0.50
    physBack     | [W: 32.4, H: 140.0, D: 1.0]   | [0.0, 14.0, 3.5]            | Fric: 0.1, Rest: 0.50

    By restricting translation to the depth interval of Z ∈ [-3.5, 3.5], the solver
    absorbs depth forces into physical wall friction, maintaining coplanar stability.

4. TRAVERSAL KINEMATICS & PLAYER STATE MACHINE
-------------------------------------------------------------------------------
Player locomotion and coordinate translation are governed by `PlayerKinematicsSystem.ts`,
interacting with three separate concrete state classes implementing `IPlayerState.ts`.


              +-------------------+
              |     AIRBORNE      |
              +---------+---------+
                        |
       Wall collision & | Input release /
       Pressing into wall | Fling launch
                        v
              +---------+---------+
              |   WALL_STICKING   |
              +---------+---------+
                        |
       Fling transition | Timer expiry /
       with tension >= 0.427 | Launch completed
                        v
              +---------+---------+
              |    LAUNCHING      |
              +-------------------+


4.1 Airborne State (`PlayerAirborneState.ts`)
    - Integration:
      ```
      V_y(t) = V_y(t-1) + G_kinematic * dt
      V_x(t) = V_x(t-1) + Input_x * F_swing * dt
      ```
      Where `G_kinematic = -24.0 m/s²` and `F_swing = 36.0 m/s²`.
    - Drag:
      ```
      V(t) = V(t) * (D_drag)^(dt * 60.0)
      ```
      Where `D_drag = 0.99`.
    - Wall Cling Evaluation: Spawns horizontal raycasts of length 0.15m. If the player
      intersects a wall boundary (X = +/- 14.2) and inputs a lateral steering vector
      towards that wall, they enter the `WALL_STICKING` state.

4.2 Wall Sticking State (`PlayerWallStickingState.ts`)
    - The player grips a static wall or crawling hazard. Lateral velocity is locked to zero.
    - Slide Velocity: Clamped to:
      ```
      V_y = -V_slide + V_recoil
      ```
      Where `V_slide = 5.0 m/s` (base slide speed) and `V_recoil` represents residual recoil forces.
    - If sticking to a crawling minion, the slide velocity is conformed to the hazard's speed:
      ```
      V_y = -(V_slide + V_hazard_speed)
      ```
    - Charging Fling: The player charges a launch vector. The duration of charging is tracked 
      by `trav.chargeTimer` once tension exceeds `0.427`.

4.3 Launching State (`PlayerLaunchingState.ts`)
    - Gravity is scaled down to allow linear trajectories:
      ```
      G_launch = G_kinematic * 0.22 = -5.28 m/s²
      ```
    - Steering correction:
      ```
      V_x(t) = V_x(t-1) + Input_x * F_launch_steer * dt
      ```
      Where `F_launch_steer = 16.0 m/s²`.
    - Exits automatically to `AIRBORNE` when the launch timer expires (`0.7` seconds).

4.4 Tension & Length-Capping Mechanics
    - Tautness Ratio ($R_{taut}$):
      $$R_{taut} = \frac{L_{current}}{L_{max}}$$
    - Elastic Tension Formula ($T$):
      $$T = \text{clamp}\left(0.0, T_{max}, \frac{R_{taut} - 0.85}{0.15}\right)$$
      Where `0.85` is the tautness threshold. Tension remains `0` inside the slack zone ($R_{taut} < 0.85$).
    - Dynamic Tension Limit ($T_{max}$):
      To prevent immediate cord snaps when reeled close, the ceiling of maximum achievable
      tension is scaled dynamically by the current rope length:
      $$T_{max} = \text{clamp}\left(0.15, 1.0, \frac{L_{max} - L_{min\_limit}}{L_{max\_limit} - L_{min\_limit}}\right)$$
      Where $L_{min\_limit} = 5.4$ and $L_{max\_limit} = 38.0$.

4.5 Tension Release & Fling Trajectories
    When releasing the wall, the launch trajectory is calculated based on tension stages:
    - Stage 1: Slack Zone ($T < 0.427$):
      The player drops into a falling trajectory with a gentle horizontal nudge:
      $$V_{launch} = [N_{wall} \cdot 5.5, \max(V_y, -3.0), 0] \text{ m/s}$$
      Where $N_{wall}$ is the wall normal.
    - Stage 2: Taut Zone ($0.427 \le T < 0.8$):
      Launches the player towards the stinger tip:
      $$V_{launch} = \vec{D}_{anchor} \cdot I_{fling} \cdot 0.55 \cdot S_{length\_scalar} \cdot R_{charge} \cdot B_{bonus}$$
      Where $I_{fling} = 76.0 \text{ m/s}$, $S_{length\_scalar}$ scales power based on extended rope length,
      $R_{charge}$ is the charge ratio, and $B_{bonus}$ is the web-struggle bonus multiplier (1.15).
    - Stage 3: Overloaded Zone ($T \ge 0.8$):
      Maximum kinetic release. The base power ratio is set to $0.90$. Triggers custom chromatic 
      aberrations and hitstop time-dilation.

4.6 Reeling Dynamics (`TetherReelingSystem.ts`)
    - Manual Reel-In: Activated by pressing UP. Contracts the tether's maximum limit at a
      rate of `-16.0 m/s`.
    - Rope Length Solver:
      The maximum length ($L_{max}$) is interpolated towards the desired length ($L_{desired}$)
      using an analytical spring-damper solver:
      ```
      [L_max, V_reel] = solveSpringDamper(L_max, L_desired, V_reel, dt, K_stiffness, D_damping)
      ```
      Where `K_stiffness = 180.0` and `D_damping = 15.0`.

4.7 Violent Snap-Back recoil (`TetherStrainSystem.ts`)
    If tension reaches $1.0$ (SNAP_LIMIT), the system registers a damage strike.
    To prevent instant player death, the system triggers a Violent Snap-Back:
    1. Forces the player off the wall into `AIRBORNE` with a $0.5$s control stun.
    2. Cuts the allowed thread capacity immediately in half ($L_{max} \leftarrow L_{max} \cdot 0.5$).
    3. Whips the player towards the stinger tip at high velocity:
       $$V_{snap} = \vec{D}_{anchor} \cdot 55.0 \text{ m/s}$$
    4. Applies a hard squash animation to the Weaver: $ScaleVel = [-28.0, 18.0, 0]$.
    5. The third consecutive strike snaps the thread completely, causing instant death.

5. WEAVER BOSS AI & COMBAT PIPELINE
-------------------------------------------------------------------------------
The Weaver's behavioral AI is modeled as a state machine processing five operational states:


        +-------------------+
        |    PATROLLING     | <-------------------------+
        +---------+---------+                           |
                  |                                     |
Damaged / Bounced | Return ceiling                      | Arrived at
by player         | condition                           | ceiling Y
                  v                                     |
        +---------+---------+   Strike recovery /       |
        |     STRIKING      | +---------------------+   |
        +---------+---------+ | Contract tether &   |   |
                  |           | Fire web projectile |   |
         Weaver   |           v                     |   |
         bounced  |     +-----+-------------+       |   |
                  |     |     SHOCKWAVE     |       |   |
                  |     +-----+-------------+       |   |
                  v           |                     |   |
        +---------+---------+ | Blast complete      |   |
        |    ASCENDING      | <---------------------+---+
        +---------+---------+



5.1 Patrolling State (`WeaverPatrollingState.ts`)
    - Moves horizontally along the ceiling ($Y = 34.0$) between the left and right walls ($X = \pm 14.2$).
    - Sweep Logic:
      Translates at speed $V_{patrol} = 4.5 \text{ m/s}$ (normal) or $V_{patrol} = 9.0 \text{ m/s}$ (berserk).
      Upon hitting a wall, the Weaver pauses for a 0.22s hold period, reverses direction, and launches
      with a temporary 2.0x velocity boost.
    - Web Projectile Telegraph:
      The Weaver pauses horizontal movement and glows yellow for $1.4$s (telegraph duration).
      On expiry, it launches a target web projectile.

5.2 Striking State (`WeaverStrikingState.ts`)
    - Prep Phase:
      The Weaver halts and squashes its body ($ScaleY = 0.82$, $ScaleX = 1.15$). It shivers for $0.6$s
      while drawing back along the thrust line.
    - Thrust Phase:
      Lunges directly towards the player's last registered coordinates at high velocity:
      $$V_{thrust} = 28.0 \text{ m/s (normal) or } 36.0 \text{ m/s (berserk)}$$
    - Recover Phase:
      The Weaver pauses for $0.5$s, stretches on impact, contracts the player's tether capacity by 25%,
      and fires a target web projectile.

5.3 Shockwave State (`WeaverShockwaveState.ts`)
    - Triggered if the player collides with the Weaver during its normal patrol.
    - Telegraph Phase:
      The Weaver glows gold, shivers, and expands its scale to $1.25$ for $0.85$s.
    - Blast Phase:
      Releases a circular shockwave (radius: $6.8$m). It spawns 3 concentric torus meshes
      expanding at $22.0 \text{ m/s}$.
    - On contact, the player takes 1 HP damage, experiences a heavy knockback, and has their
      unreeled thread reeled back to the default baseline ($5.4$m).

5.4 Ascending State (`WeaverAscendingState.ts`)
    - Climbs vertically back to its ceiling altitude ($Y = 34.0$) at a rate of $12.0 \text{ m/s}$.
    - Continuously reels the player's thread back to the starting baseline of $5.4$m at a fast
      reeling rate of $22.0 \text{ m/s}$.

5.5 Defeated State (`WeaverDefeatedState.ts`)
    - Scale drops to $0.2$. The legs collapse ($GaitTuck = 0.82$). The boss drops out of play
      under gravity.

6. PROCEDURAL SHADER PIPELINE & TEXTURE GENERATION
-------------------------------------------------------------------------------
Project Silk implements a custom material pipeline leveraging vertex-displacement 
and fragment shaders to render organic damage deformations and dynamic textures.

6.1 Dynamic Vertex Shear Displacement (`SilkMaterialPlugin.ts`)
    When the Weaver is damaged, its mesh is deformed in real-time along the horizontal
    plane using a vertex-shear shader.
    - Displacement Equation ($D_{shear}$):
      $$D_{shear} = \text{floor}\left(\frac{P_y}{T_{size}}\right) \cdot T_{size} \cdot \sin\left(\text{floor}\left(\frac{P_y}{T_{size}}\right) \cdot T_{size} \cdot 20.0 + t \cdot 75.0\right) \cdot E(y, t) \cdot I_{damage}$$
      Where $P_y$ is the vertex local Y position, $T_{size} = 0.16$ is the quantization tile size,
      $I_{damage}$ is the damage intensity, and $E(y, t)$ is a Gaussian shiver envelope:
      $$E(y, t) = \max\left(0.0, 1.0 - \frac{|P_y - (2.5 - t \cdot 10.0)|}{1.8}\right)$$
    - Normal Vector Reconstruction:
      To maintain correct specular lighting, normal vectors are reconstructed in the vertex shader
      via finite differences using an epsilon step ($\epsilon = 0.02$):
      $$N_{sheared} = \text{normalize}\left(\vec{N} - \left[\frac{D_{shear}(P + \epsilon_y) - D_{shear}(P)}{\epsilon}, 0, 0\right] \cdot 0.35\right)$$

6.2 Vertex Noise Displacement (Cocoon Web Shading)
    Used to deform projectile meshes and web-trapped cocoons.
    - Displacement value ($D_{noise}$):
      $$D_{noise} = \left(\sin(P_x \cdot 2.0 + t \cdot 5.0) \cdot \cos(P_y \cdot 2.3 + t \cdot 6.3) \cdot \sin(P_z \cdot 2.6 + t \cdot 4.1) + \sin(P_y \cdot 5.0 - t \cdot 11.0) \cdot 0.35\right) \cdot 0.24$$
    - Vertices are displaced along their normal vectors:
      $$P_{new} = P + \vec{N} \cdot D_{noise}$$
    - Normal vectors are re-calculated using a 3D finite difference gradient:
      $$\vec{G} = \frac{1}{\epsilon} \left[ D_{noise}(P + \epsilon_x) - D_{noise}(P), D_{noise}(P + \epsilon_y) - D_{noise}(P), D_{noise}(P + \epsilon_z) - D_{noise}(P) \right]$$
      $$\vec{N}_{new} = \text{normalize}(\vec{N} - \vec{G} \cdot 0.5)$$

6.3 Fragment Abdomen Under-Glow Shading
    A fragment shader maps a soft bioluminescent under-glow along the Weaver's lower abdomen.
    - Gradient Factor ($F_{glow}$):
      $$F_{glow} = \text{smoothstep}(0.0, 3.4, -P_{y\_local})^{2.5}$$
    - Color Blend:
      $$C_{final} = C_{base} + C_{emissive} \cdot F_{glow}$$

6.4 Procedural PBR Texture Generation (`ProceduralTextureGenerator.ts`)
    Textures are generated programmatically at boot on dynamic HTML5 canvas contexts using 
    Fractional Brownian Motion (fBm) noise.
    - fBm noise function ($f(x, y)$):
      $$f(x, y) = \sum_{i=0}^{3} A_i \cdot \text{noise}(x \cdot F_i, y \cdot F_i)$$
      Where $A_0 = 0.5$, $F_0 = 1.0$, $A_{i+1} = A_i \cdot 0.5$, and $F_{i+1} = F_i \cdot 2.0$.
    - Normal Map: Generated by calculating horizontal and vertical gradients on the
      displacement height map, and storing them in the RGB channels:
      $$\text{Color}_{normal} = \left[ (dx \cdot 0.5 + 0.5), (dy \cdot 0.5 + 0.5), dz \right] \cdot 255$$
    - ORM Map: Packs three channels:
      * Red: Ambient Occlusion ($AO = 1.0 - (1.0 - height) \cdot 0.3$)
      * Green: Roughness ($R_{rough} = R_{min} + (1.0 - height) \cdot (R_{max} - R_{min})$)
      * Blue: Metalness ($M_{metallic} = 0.95 \cdot 255$)

7. TETHER ROPE & DOUBLE-STRAND SNAPPING MODEL
-------------------------------------------------------------------------------
The tether rope is rendered as a dynamic cylinder tube mesh re-triangulated every
frame using a quadratic Bezier curve solver.

7.1 Bezier Curve Geometry
    The rope curve is defined by an anchor point ($\vec{A}$), a player attachment
    point ($\vec{P}$), and a control point ($\vec{C}$) that determines the rope sag:
    $$\vec{B}(t) = (1-t)^2\vec{A} + 2(1-t)t\vec{C} + t^2\vec{P}$$
    Where $t \in [0, 1]$ represents the segment index along $24$ segments.

7.2 Control Point & Sag Solver
    The control point coordinates are calculated dynamically to represent gravity sag
    and reeling tension:
    $$\vec{C} = \left[\frac{\vec{A} + \vec{P}}{2}\right] - [0, S_{sag}, -0.35]$$
    - Sag height ($S_{sag}$):
      $$S_{sag} = S_{max\_sag} \cdot (1.0 - T_{tension}) + \text{Osc}_{vibe}$$
      Where $S_{max\_sag} = 3.8$m.
    - Cable Vibration Offset ($\text{Osc}_{vibe}$):
      If tension exceeds $0.7$, the rope vibrates at high frequency:
      $$\text{Osc}_{vibe} = \sin(\text{time} \cdot \omega_{vib}) \cdot (T_{tension} - 0.7) \cdot A_{vib}$$
      Where $A_{vib} = 0.35$ and $\omega_{vib} = 0.025$. If tension reaches $0.95$, the frequency
      and amplitude are amplified by $3.5$x and $2.5$x respectively.

7.3 Wind Wave Disturbances
    To simulate continuous motion, a low-amplitude, high-frequency wave is applied
    to the rope's depth coordinates:
    $$P_z = P_z + \sin(t \cdot 2.5 + \text{time} \cdot 0.005 + \phi_{reel}) \cdot A_{wave}$$
    Where $A_{wave} = 0.12$m, and $\phi_{reel}$ is a phase offset proportional to the reeling speed.

7.4 Double-Strand Snapping model
    When the tether breaks, the rope splits into two separate strands, simulating tension recoil
    over a $1.5$-second decay period:
    - Anchor Strand ($\vec{B}_{anchor}$):
      Formed by the first $12$ segments of the curve. The free end snaps away from the break 
      point with a high-frequency sine-wave whip offset:
      $$\text{Whip}_{anchor} = \sin(t_{snap} \cdot 5\pi) \cdot (1 - t_{snap}) \cdot 1.8 \text{ meters}$$
    - Player Strand ($\vec{B}_{player}$):
      Formed by the remaining $12$ segments of the curve. The free end snaps back towards the
      player, falling under gravity as the recoil decays:
      $$\text{Fall}_{player} = t_{snap}^2 \cdot G_{gravity} \cdot 0.8$$

8. JUICE, IMPACT DEFORMATION, & SHATTER MECHANICS
-------------------------------------------------------------------------------
Project Silk implements several dynamic visual features to enhance game feel,
including procedural mesh shattering, spring-damper squash animations, and object pools.

8.1 Spring-Damper Squash & Stretch (`EngineUtils.ts`)
    Visual models deform on wall impacts, launches, and landings. Deformations are
    solved using an analytical spring-damper formula:
    $$f(t) = \text{solveSpringDamper}(x_{current}, x_{target}, v_{velocity}, dt, K_{stiffness}, D_{damping})$$
    - Player Spring Constants: $K = 220.0, D = 14.0$.
    - Weaver Spring Constants: $K = 120.0, D = 22.0$.
    - Wall Impact Squash: When colliding with a wall, the player's scale instantly squashes:
      $$ScaleX = \max(0.3, 0.72 - I_{speed} \cdot 0.35)$$
      $$ScaleY = \min(2.0, 1.22 + I_{speed} \cdot 0.50)$$
      And then bounces back to a neutral $1.0$ scale over time.

8.2 Runtime Mesh Shattering (`WeaverShatterSystem.ts`)
    When the Weaver dies, its icosphere mesh is procedurally shattered at runtime:
    - Shard Generation:
      Calculates the centroids of the 20 triangular faces of the icosphere shell,
      and spawns individual 3-vertex triangular meshes centered at those points.
    - Core Pyramids:
      Generates 8 inner triangular pyramids (4-vertex meshes) from the core coordinates
      facing outwards.
    - Shard Physics:
      Each shard is assigned an initial linear velocity directed outwards from the centroid:
      $$V_{shard} = \vec{D}_{outward} \cdot V_{speed} + \vec{V}_{variance}$$
      Where $V_{speed} \in [5.0, 19.0] \text{ m/s}$. Air drag ($D_{drag} = 0.95$) and gravity
      ($G_y = -38.4 \text{ m/s²}$) are integrated every frame.
    - Collision Handling:
      Shards bounce off the side walls and push away from each other on intersection:
      $$P_{offset} = \vec{D}_{normal} \cdot \left( (R_1 + R_2) - \text{distance} \right) \cdot 0.5$$

8.3 Dynamic Projectile Splatting (`WebShatterSystem.ts`)
    Similar to the Weaver shatter system, breaking free from a web cocoon triggers a
    splat animation. It spawns $12$ procedural shards (alternating spheres and boxes) that
    recoil away from the player with randomized angular velocities ($\omega_{var} = \pm 6.0 \text{ rad/s}$)
    and scale down to zero over $1.2$ seconds.

8.4 Object Pools
    To prevent garbage collection stutter, dynamic hazards and projectiles are managed
    using pre-allocated pools:
    - Projectiles: Pool size = $16$ (`ProjectilePool.ts`).
    - Flying Health Bugs: Pool size = $2$ (`HealthBugPool.ts`).
    - Spike Bugs: Pool size = $4$ (`SpikeBugSystem.ts`).
    - Wall Bugs: Pool size = $2$ (`WallBugSystem.ts`).
    All instances are created at boot, hidden out of bounds, and reset/re-allocated via index cycling.


-------------------------------------------------------------------------------
9. AUDIO PIPELINE & SYNTHESIS SPECS
-------------------------------------------------------------------------------
The audio engine (`AudioSystem.ts`) manages spatial sound effects and background
ambience using Tone.js and raw Web Audio nodes.

9.1 Atmospheric Wind Synthesis (`ProceduralAmbienceEngine.ts`)
    Generates dynamic wind sound effects programmatically without using audio files.
    - Web Audio Graph Design:
      ```
      [White Noise Source] -> [Lowpass Filter 1 (800Hz)] -> [Lowpass Filter 2 (300Hz)] -> [Gain] -> [Destination]
                                                                  ^
                                                                  | Cutoff Frequency
                                                            [LFO (0.2Hz)] -> [LFO Gain (10)]
      ```
    - The LFO modulates the cutoff frequency of the second low-pass filter, creating
      procedural wind gusts.
    - The gain is smoothed over 2.0s during startup using a linear ramp.

9.2 Auditory Fatigue Mitigation (Pitch/Gain Variance)
    To keep repetitive sound effects from sounding monotonous, sample playback rates
    and volumes are randomized slightly on every trigger:
    - Playback Rate Correction (detune):
      $$Rate_{playback} = 2^{\frac{\Delta_{cents}}{1200}}$$
      Where $\Delta_{cents}$ is a random detune offset between $\pm 50$ and $\pm 250$ cents.
    - Volume Gain Offset: Randomized within a range of $\pm 2.5$ dB.


-------------------------------------------------------------------------------
10. USER INTERFACE & STATE SYNCHRONIZATION
-------------------------------------------------------------------------------
The UI layer is written in React 19, synchronized with the ECS system loop using
Zustand stores.

10.1 Synchronization Bridge (`HudSyncSystem.ts`)
     Coordinates state updates between React and the ECS:
     - Component stores are read at the end of every frame (Phase 7: `PostRender`), and
       changes in health, tension, state, and calibration are dispatched to the Zustand store.
     - To avoid React render cycles during high-frequency updates (such as the tension bar),
       the ECS bypasses React state entirely, writing width, color, and glow shadows
       directly to DOM elements using vanilla JS ref handles on a custom `silk-tension-render-tick`
       event.

10.2 Web Trap Cocoon Mechanics (`PlayerStateUtils.ts`)
     - Accumulating Traps:
       Every web projectile impact increases the player's web mass ($W_{mass} \leftarrow W_{mass} + 1$).
       This scales the visual size of the cocoon, slows player acceleration, and increases
       the required struggle inputs:
       $$Inputs_{required} = 5 + (W_{mass} - 1) \cdot 3$$
     - Web Struggle Resolution:
       To break free, the player must alternate directional inputs ($A/D/W/S$ or arrows).
       Each successful direction change advances their progress ($P_{escape} \leftarrow P_{escape} + 1$)
       and triggers a camera shake. Upon reaching the target threshold, the cocoon breaks.
