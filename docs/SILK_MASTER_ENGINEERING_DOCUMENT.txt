1. EXECUTIVE SUMMARY & DESIGN PHILOSOPHY
-------------------------------------------------------------------------------
SILK is a high-performance vertical arena action game. To guarantee 60Hz 
stability and prevent race conditions, the architecture strictly decouples 
subsystems into isolated layers orchestrated by a central SystemManager.

- React: Strictly for static UI layout mounting.
- Babylon.js: Visual presentation and render pass.
- Rapier WASM: Authoritative physics transforms and constraints.
- Gameplay Systems: Pure logic operating on pure data components.
- DOM HUD: Bypasses React VDOM for 60Hz direct DOM mutations.

2. THE NERVOUS SYSTEM: FRAME EXECUTION PIPELINE
-------------------------------------------------------------------------------
The GameLoop enforces a strict, sequential Tick Pipeline. Every system 
registered in the SystemManager executes in this exact order during the 
fixed update step (dt = 1/60s):

1. Input Phase: PlayerInputSystem polls DOM/Keyboard, writes to InputBuffer.
2. Simulation Phase: PlayerMovementSystem & WardenBrainSystem read inputs 
   and apply forces/intents to Physics Controllers.
3. Physics Phase: RapierWorldSystem steps the WASM world, resolving 
   constraints, collisions, and integrating velocities.
4. Sync Phase: TransformSyncSystem reads Rapier rigid bodies and writes 
   to Babylon Mesh transforms.
5. Audio Phase: AudioDirectorSystem reads continuous physics state and 
   processes discrete domain events.
6. Camera Phase: CameraSystem targets the synced Player mesh, applies 
   spring math and shake offsets.
7. Render Phase: RenderSystem & LightingSystem execute the Babylon WebGL 
   draw call (using the interpolation alpha).
8. UI Phase: DomHudSystem reads throttled state and mutates DOM nodes.

3. ARCHITECTURAL PATTERNS & SOLID COMPLIANCE
-------------------------------------------------------------------------------
- Dependency Inversion (DIP): Engine is a pure orchestrator. CompositionRoot 
  acts as the DI container, wiring all systems and injecting dependencies.
- Single Responsibility (SRP): Strict Component-System pattern. Entities are 
  pure data structures (PlayerData, WardenData). Systems contain all logic.
- Interface Segregation (ISP): Physics exposes IReadablePhysics and 
  IWritablePhysics boundaries to prevent tight coupling with Render.
- Open/Closed (OCP): Warden AI uses a formal State Pattern (IWardenState). 
  Adding new states requires zero modifications to the WardenBrainSystem.
