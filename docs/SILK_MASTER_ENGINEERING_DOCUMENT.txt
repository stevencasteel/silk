[AI ASSISTANT GUIDELINES: HAVOK V2 PHYSICS]
When expanding or optimizing physics-driven mechanics, adhere to the Babylon.js V2 Physics API (Havok) best practices:
1. Object Pooling: Prefer separating collision bounds and mass by instantiating a 
   reusable PhysicsShape and binding it to individual PhysicsBody instances. 
   Avoid the PhysicsAggregate wrapper for large pools to save memory.
2. Legacy Code: Ensure no V1 PhysicsImpostor syntax is generated.
3. 2D Constraints: When constraining 3D physics to a 2D plane, rely on static 
   invisible glass walls to natively sandwich the simulation plane rather than 
   manually clamping the Z-axis in the render loop.

1. PLAY AREA, ALIGNMENT & STATIC CAMERA SPECIFICATIONS
===============================================================================
- Playable Area limits: Left/Right X: [-15.0, 15.0], Floor/Ceiling Y: [-8.0, 38.0]
- Vertical Boundaries: Flat solid PBR walls at X = -15.0 and X = 15.0. Measurement 
  unit ticks scroll downwards continuously, managed by ParallaxScrollSystem, 
  creating the endless vertical ascension illusion.
- 2D Physics Plane: The Z-axis is constrained natively via invisible front and 
  back static Havok collision walls at Z = 3.5 and Z = -3.5.
- Camera Position Tracking:
  * Default Locked Camera: Fixed perspective looking at (0, 14, 0).
  * Patrol State Behavior: When the Weaver is in the PATROLLING state, camera 
    vertical panning is completely locked. Because the player's maximum thread 
    length is calibrated to 38.0 units, the player naturally dangles above the 
    tension UI (at Y ≈ -1.24) and cannot slip out of the viewport.
  * Engaging/Strike State Behavior: Panning lock automatically releases only 
    when the Weaver descends to attack (STRIKING, SHOCKWAVE, or ASCENDING). If 
    the player is forced past the bottom comfort limit (Y < -11.5) because the 
    Weaver dashed down, the camera dynamically pans down to track them.
  * Panning Recovery: Returns smoothly back to static baseline coordinates 
    (Y = 14.0) once combat actions are completed.

2. REALIZED CORE TRAVERSAL & PHYSICS SKELETON
===============================================================================
- GHOST ENTITIES (KINEMATICS):
  The Player and Weaver move via strict custom trigonometric ECS logic (processed 
  by PlayerKinematicsSystem and WeaverTraversalSystem), but exist in the Havok 
  simulation as ANIMATED (Kinematic) PhysicsBodies. This allows Havok to track 
  their exact hitboxes natively without gravity interfering.

- DECOUPLED PLAYER LOCOMOTION STATE MACHINE:
  Player movement kinematics are modeled using a strict state machine pattern. 
  PlayerKinematicsSystem delegates coordinate updates and velocity checks to 
  isolated classes implementing the IPlayerState interface inside the 
  `src/gameplay/player/states/` directory:
  1. AIRBORNE (PlayerAirborneState): Translates swing inputs, gravity metrics, 
     drag damping, and detects limits.
  2. WALL_SLIDING (PlayerWallSlidingState): Handles friction factors, WallBug 
     attaching coordinates, and vertical slide inputs. Passive tension charging is disabled.
  3. LAUNCHING (PlayerLaunchingState): Integrates high-speed sling release 
     forces, launch damping, and checks limit boundaries.

- THE TETHER AS A ONE-WAY RATCHET:
  1. Elongation: The maximum length of the rope can only increase while wall sliding.
  2. Instant Reeling: Reeling slack updates maxLength immediately.
  3. Strict Fall Clamp: Momentum converts cleanly into a pendulum arc when arrested.

- PHYSICS-BASED ELASTIC TENSION:
  * Elastic Tautness: Passive wall-slide tension is removed. Tension is calculated 
    purely based on physical stretch: Tautness = currentLength / maxLength.
  * Tautness Threshold: Tension begins building once Tautness exceeds 85%, scaling 
    up to 1.0 (and 1.3 under extreme overload).
  * Progress-Linked Tension Cap: The maximum achievable tension is capped 
    proportionally to the current reeled-out progress: (maxLength - 7.0) / (38.0 - 7.0).
  * Safe Spawn dangling: At starting unreeled spawn length (maxLength = 12.0), 
    tension is capped at a safe 0.15 (Stage 1 / Green), preventing instant deaths.
  * Fling Launch Zones:
    - Stage 1 (Green Zone, Tension < 0.375): Safe release. Letting go of the 
      wall simply detaches the player into standard airborne falling trajectory 
      with a gentle, controlled outward nudge. No launch speed is applied.
    - Stage 2 (Yellow Zone, 0.375 <= Tension < 0.80): Standard Fling Launch. 
      Launches player towards Weaver stinger tip at high velocity.
    - Stage 3 (Red Zone, Tension >= 0.80): Extreme Fling Launch. Unlocks only 
      when the line has been unreeled to its upper limit on the wall, enabling 
      powerful lunge attacks.

3. COMBAT, DYNAMIC WEAVER REELING & SHOCKWAVE RECOVERY
===============================================================================
- COMBAT MELEE SHOCKWAVE REEL-IN:
  * Cocoon Shockwave: During WeaverShockwaveState, if the player is caught inside 
    the shockwave's radius (6.8 units) in a vulnerable state, they take damage and 
    are instantly reeled back to the compact, starting initial length (maxLength = 12.0).

- WEAVER STRIKE SEQUENCE & 25% RETRACTIVE REEL-IN:
  * Damaging the Weaver triggers her STRIKING combat state (PREP -> THRUST -> RECOVER).
  * Recovery Transition: When transitioning from the strike dash (THRUST) to recover 
    (RECOVER), the Weaver reels the player in by 25% (pTether.maxLength *= 0.75).
  * Targeted Combat Shot: Immediately upon entering recovery, the Weaver fires a 
    targeted web projectile targeting the player's exact coordinates.
  * Ascension Reel-In: While the Weaver climbs back to her patrol ceiling line in 
    WeaverAscendingState, she simultaneously reels the player's tether back down 
    to the baseline default initial length (maxLength = 12.0).

4. TENSION UI BAR REWORK & COLOR GRAMMAR
===============================================================================
- DUAL-PURPOSE TENSION BAR UI:
  * Reeled-Out Progress: The progress bar filled width representing 0% to 100% 
    corresponds to how much tether capacity (slack/reel of tether) has been 
    unreeled (from 7.0 to 38.0 units).
  * Elastic Tautness Glow: The bar's color and pulsing glow reflect the current 
    elastic tension:
    - Green (Tension < 0.375): Slack / Stage 1. No active glow.
    - Yellow (0.375 <= Tension < 0.80): Taut / Stage 2. Active amber glow.
    - Red (Tension >= 0.80): Overloaded / Stage 3. High intensity crimson pulse.

5. THE FLYING HEALTH BUG SYSTEM & COLLISION KINETICS
===============================================================================
- DYNAMIC SPATIAL LIFECYCLE:
  * Flying minions (Health Bugs) spawn from the bottom of the corridor with a 
    high frequency (testing interval: 1.5s) and fly vertically upwards.
  * Upon reaching the middle of the playable viewport, they pause for 3 to 6 
    seconds, then continue their ascent out of bounds.

- RE-CALIBRATED INTERACTION STAGES:
  * Stage 0 & 1 (Slack release, launchPower < 0.375): Harmless elastic overlaps. 
    Player safely bumps or gently shoves the bug without popping.
  * Stage 2 (Active Fling, 0.375 <= launchPower < 0.80): High-momentum shove. 
    Bounces harmlessly unless spiked, which pops the bug and damages the Weaver.
  * Stage 3 (Overloaded Tension, tension >= 0.80 / launchPower >= 0.80): 
    Extreme kinetic impact. Pops standard bugs immediately, spawning seek-healing 
    green particles that fly to the HUD's HP slots, or activates high-velocity 
    wall-bouncing pinball mode.
